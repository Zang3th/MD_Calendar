# Shell

The frame around all views: header, backlog panel, entry dialog and notifications. Visual values are defined in the [Design System](DesignSystem.md). The UI language is English; labels below are the exact UI texts.

## Page layout

- A floating glass **header pill** at the top, the **main panel** below it, both with a small gap to the window edge.
- There is no sidebar.

## Start card

While no folder is open, the main panel shows a centered card with the heading “Recent folders”, the list and the buttons “Open folder” and “New calendar”. Logo, name and version are shown only in the header, as in MD_Manager. The header shows the logo, “MD_Calendar”, the version label, help and the sound toggle; all controls that need a folder are hidden.

- **Recent folders**: the five most recently opened folders, most recently opened first, each with its name and, at the right, when it was last opened on this device: the day (“Today”, “Yesterday” or `DD.MM.YYYY`) above the time (`HH:MM`). Below the name a smaller line shows what the folder's `MD_Calendar.json` says: the path entered for this device, the number of devices and the device that saved last (“2 devices · saved on MacBook”, “saved on this device”). The line comes from a copy kept when the folder was last opened or saved; when the browser still grants access, the start card reads the file again and updates the line. Without any of these facts the line is left out. Clicking a row opens the folder (asks for permission if needed). The × at the end of a row removes the folder from the list; the folder itself is not touched. Without recent folders the list says “No recent folders”.
- **Open folder** (primary button) chooses a folder with the system dialog, opens it and adds it to the list.
- **New calendar** (secondary button) chooses a folder, adds `MD_Calendar.json` to it and opens it; Markdown files already in the folder are kept. A folder that already has the file simply opens.
- Only a calendar folder opens, one that holds `MD_Calendar.json` (see [DataFormat](../DataFormat.md#md_calendarjson)). Opening any other folder, by “Open folder”, a recent folder or at startup, keeps the card open with the warning “Not a calendar folder”; the body names the folder and says to set it up with [New calendar].
- If the browser still grants access to the most recently opened folder, it opens at startup without the card. If that folder no longer exists (moved, renamed, deleted or its drive not mounted), the card stays open with the warning “Last folder not found”; clicking such a row shows “Folder not found”. The body names the folder and says to open it from its new place. Without permission the card stays open silently. The folder stays in the list, so that it opens again once it is back.
- Clicking the logo in the header returns to the start card. It reloads the page, so unsaved changes trigger the browser's leave prompt; the next startup then shows the card instead of opening the last folder.
- **Version and watermark**, as in MD_Manager: the header shows the version label (`v0.7.0`) next to “MD_Calendar”, and the bottom left corner shows the watermark “© 2026 MD_Calendar v0.7.0 · Tim Krüger (Zang3th) · GitHub”. Both appear only on the start card. The version comes from `package.json` (see [Architecture](../Architecture.md#runtime)); between releases it carries the next release with `-dev`.
- The header has the same height on the start card and in the views (58px), so that nothing moves when a folder opens.

## Header

Three zones in one row. The center zone is always exactly centered.

| Zone | Content, left to right |
|---|---|
| Left | Logo (back to the [start card](#start-card)) · current month and year (for example “November 2026”) · **+** · undo · redo · save control |
| Center | View switcher **Week · Month · Contacts** with a sliding indicator; the three options have the same width |
| Right | Holiday overview · backlog toggle · help · sound toggle · options (three lines) |

- **+**, undo, redo and the save control follow the title as one group, in the order of MD_Manager. There are no arrows and no week number badge; weeks and months change with `←`/`→`, the mouse wheel and a click on the title (today).

- There is no "today" button. Clicking the month title jumps to today.
- The title keeps the width of its longest text (the longest month name, “Contacts”), so that the buttons next to it do not move when the month changes.
- The right zone uses plain icon buttons without separators or nested frames. A surface appears on hover. Help, the sound toggle and the options sit at the far right and are also shown on the start card; they keep their position when a folder opens.
- **+** opens a menu below it with the ways to add; a click on an item runs it. In the calendar views the items are “Create new entry” and “Import .ics event”, in the contacts view “Create new contact” and “Import .ics event”. The file type `.ics` shows as code: monospace on a tinted chip. While the menu is open, the plus turns by 45° into a “×” and a soft accent ring surrounds the button, so it reads as “close”. A second click on **+**, Escape or a click outside closes the menu. `A` still creates a new entry or contact directly.
- “Import .ics event” chooses an `.ics` file and imports it into the open calendar (see [Domain](../Domain.md#ics-import)); a notification reports the result. It is offered in every view; from the contacts view the import switches to the calendar.
- Options (three horizontal lines, “Options”) opens a menu below the button, aligned to its right edge; while it is open the button keeps its surface, like the holiday overview and help. Its first and so far only item is the switch “Hide icons” (see [Settings](#settings)).
- Help (question mark after MD_Manager) toggles the [help panel](#help).
- The backlog toggle shows no count. It is highlighted while the backlog panel is open.
- In the contacts view the title reads “Contacts”.
- The holiday overview button (calendar with a star, the holiday icon) opens the panel described in [Views](Views.md#holiday-overview).
- **+** is an icon-only primary button. It creates an entry, in the contacts view a contact.
- Portrait and windows up to 1300px wide: everything stays in one row; the view switcher shows icons only and the save control is an icon button (see [Save control](#save-control)).

### Search

There is no search button. `F` opens a search bar centered at the bottom edge of the window; at first it shows only the field. While typing, up to 30 hits appear above the field (rules in [Domain](../Domain.md#search)); without hits it says “No results”. Each hit shows its tag icon or kind icon, the title and its date (“from …” for a series, a range for multi-day entries, “Backlog”). Arrow keys and `Tab`/`Shift+Tab` choose a hit (`Tab` does not leave the field), Enter or a click jumps to it: the view shows its week or month, a month cell hiding the hit behind “+N” enlarges, and the hit is highlighted once (see [Motion](DesignSystem.md#motion)); a backlog hit opens the backlog panel. Escape or a click outside closes the bar.

### Help

The help button and `?` toggle a small floating glass panel below the button, built like the [holiday overview](Views.md#holiday-overview), with the title “Shortcuts”. It lists every shortcut and pointer gesture of [Interaction](Interaction.md). Each row has a short action on the left and the keys as key caps (`Ctrl` + `C`). Groups with pointer gestures lay every row on one grid, so that every “+” and “or” lines up: the keys, a narrow join and an end cell at the right edge. The join is “or” when key and gesture are alternatives and “+” when they go together (Ctrl + click); the end cell holds the gesture as an icon or, for a key combination without a gesture, its last key with the “+” in the join (Ctrl | + | A). A single key ends at the right edge of the card; Cut stays in line with Copy and Paste above it. Groups without gestures end with their keys at the right edge. Icons: `mouse-click` (click, left button filled; a double-click shows “2×” right before it, in the place of the join), `mouse-right-click` (right button filled), `mouse-wheel`, `mouse-middle-drag` (wheel with arrows to both sides) and `lasso` (dragging a dotted area). Each group is a card of its own (`--card` with a `--card-edge` frame, radius 12px, 10px apart, the title inside); the last card of each column fills it, so that both columns end level. The cards sit in two columns side by side so that the panel never scrolls: Views (Week W, Month M, Contacts C, Backlog B, Focus day: 2× click), Navigate (Previous / Next: ← → or wheel, Drag days: middle-button drag, Today T, Search F), Select (Area: drag, Add / Remove: Ctrl + click, Whole day: Ctrl+A) | Edit (New entry: A or click, Done / Undone: Space, Delete: Del, Copy: Ctrl+C or right-click, Paste: Ctrl+V or right-click, Cut: Ctrl+X), History (Save Ctrl+S, Undo Ctrl+Z, Redo: Ctrl+Y and below it Ctrl+Shift+Z, both right-aligned, with the label beside the first). Below both columns, without a line, one centered row holds the keys that apply everywhere: ? Help, Esc Close / Clear, Enter Confirm. The panel is 600px wide; below 760px window width the columns stack. Like the rows of the holiday overview, its rows are not interactive and have no hover highlight. Escape or a click outside closes it.

### Sound toggle

- An icon button in the header with a speaker: with sound waves while the completion sound is on, with an X while it is muted. Icons and behavior follow MD_Manager (see [Icons](DesignSystem.md#icons)).
- Muted is the pressed state (`aria-pressed="true"`). The accessible name names the action and switches with the state: “Mute” while the sound is on, “Unmute” while it is muted.
- Muting also stops a sound that is still playing.
- As in MD_Manager the state is not stored: every start begins with the sound on. Toggling is not an undoable action and is not an unsaved change.

### Undo and redo

- Disabled when nothing can be undone or redone.
- The accessible name names the concrete action, for example “Undo “Call Lena” (Ctrl+Z)”.

### Save control

| State | Appearance |
|---|---|
| Saved | The resting state: green check mark. After a save the check mark pops once. |
| Unsaved | Yellow, with a gently pulsing dot. |
| Saving | Accent color with a spinning arc, while the files are written; it stays at least 600ms, so that a quick save does not flicker and the wait for the network and the storage's write cycles is masked. |
| Failed | Red, with a cross, after a save failed; the tooltip names the error, the accessible name is “Save failed”, and an error notification reports it. The changes stay unsaved. It lasts until the next save starts or the unsaved changes change. |

The control is a 36px icon button without label or count in every layout: the icon shows the state, the accessible name carries the label with the number of unsaved changes (“Save 3 unsaved changes (Ctrl+S)”). A failed save ends “Saving” and shows “Failed”, as in MD_Manager. Clicking the control saves.

## Backlog panel

- Landscape: floating glass panel on the right, below the header; the main panel narrows to make room.
- Portrait: drawer at the bottom, about 28 % of the window height; groups are laid out side by side.
- Shows the ungrouped entries first, as a list without a head, then the groups in order. While there are no ungrouped entries their list takes no room; an entry dropped onto the panel title “Backlog” becomes ungrouped, in landscape and portrait. While an entry is being dragged, the title shows a dashed frame as the drop hint. Nothing moves when a drag starts.
- Each group head shows the name, the entry count right after it and a chevron at the right (down while open, right while collapsed). The whole head is one button that collapses the group to its head or expands it again; it gets a surface on hover. The collapsed groups are kept while the app is open, not stored. Entries look like calendar entries; they are never overdue. An empty group shows a dashed drop area.
- Opened and closed with the backlog toggle and `B`; the state is not stored. Every group is a tag; its head shows the tag icon in the tag color. A left-click on free space of the panel opens the entry dialog for a new backlog entry (“No date (backlog)”) in the group under or nearest to the pointer, with its tag preset; at the title the entry is ungrouped and untagged. Groups appear and disappear with the tags of the entries; the app creates no tags.

## Entry dialog

The dialog shows the least that is needed and the rest on request: the title and below it one strip of tokens, ended at the bottom right by Apply. There is no heading above the title (no “New entry”). Above the title at the right stand, from right to left, the icon buttons close (×), delete (trash, in `--danger`) and duplicate (copy icon); delete and duplicate only for an existing item. Close, `Esc` or a click on the backdrop closes the dialog without applying; a press that begins in the dialog, such as a text selection dragged beyond its edge, never closes it. It opens horizontally centered and 20 % of the window height above the vertical center, so that its popovers have room below. Notifications and tooltips appear above it.

- Opens on click on an entry, an occurrence or a multi-day bar, on **+** and `A` (outside the contacts view) and on a click on the body of a day. An occurrence opens its whole series. A click on free space of the backlog panel and `A` over it open it for a backlog entry (see [Backlog panel](#backlog-panel)).
- **Title** first, in a recessed field with the focus, placeholder “What is it?”. Apply and duplicate are disabled while it is empty. The dialog opens with the date popover open, or with the note popover when the item has a note. A new item has the focus in the title; an existing one opens for viewing, with the focus on the dialog and no cursor in the title, until a click moves into it or `Tab` reaches it.
- After Apply, a new entry, series, multi-day entry or backlog entry is shown in the view and highlighted once like a search hit (see [Motion](DesignSystem.md#motion)); a backlog entry only while the backlog panel is open.
- **Tokens** below the title, in this order: date, time, repeat, tag, location, note, on one line; a set token shows its icon and value in `--text`; an unset token is only its icon in `--muted`. When the line is full, set tokens drop their value and show only their icon on their background, first the tag, then repeat, time and date, until the line fits; their accessible names keep the value. Each token opens a popover 8px below the strip, horizontally centered in the dialog; no popover is taller than the date popover with its calendar, longer lists scroll; all popovers have the same width. A press elsewhere in the dialog leaves it open; it closes with its token, another token (which opens its own popover and keeps what this one holds) or `Esc`. Tokens and choices are never hidden: one the current choices rule out stays in its place, dimmed with a “not allowed” pointer, cannot be opened or picked, is skipped by `Tab`, and has no tooltip; its accessible name says why (“Not for several days”, “Not in the backlog”, “Not for a series”).
  - **Date** reads “Today”, “Tomorrow”, “Fri, 13 Nov” (with the year outside the current one), a range “13 – 15 Nov”, or “Backlog” with the inbox icon. Preselected: the clicked day, the day under the pointer for `A`, otherwise today when it is visible, else the first shown day; a backlog entry has none. The popover offers a field for typing (`DD.MM.YYYY`, `D.M.` for this year, or two dates for a range), prefilled with the chosen date (empty for the backlog); entering it selects the day, and `Tab` selects the month, then the year, before it moves on to the next token (`Shift+Tab` back); typing replaces the selection. Below the field are the pills “Today”, “Tomorrow” and “Backlog” (only for a plain entry; ruled out for a series or several days) side by side with the current one highlighted, and a month calendar. In the calendar the first click sets the day; a click on another day then makes the range between both. On a range, a click on its end or its start returns to the start as one day; a click on any other day starts over with that day. Quick choices close the popover, calendar clicks keep it open.
  - **Several days** are a range of the date: a range makes a multi-day entry, and time and repeat are ruled out, because a multi-day entry has neither (see [Domain](../Domain.md#multi-day-entry)). “Backlog” as the date rules out time and repeat as well. A time or repeat chosen before is kept in the dialog and returns when the date becomes one day again; Apply drops it otherwise.
  - **Time** reads “09:30” or “09:30–10:30”. The popover offers a field for typing (`HH:MM`, also without the colon as `1100` or `930`, a bare hour as `9`, or a range of two such as `1100-1200`), the pills “No time” and “No end”, and below them four wheels: start hour, start minute, a dash, end hour and end minute. Hours run 00–23, minutes in steps of five; the end hour starts with “–” for no end. A wheel turns by scrolling, dragging, touch, one row per notch of the mouse wheel, the arrow keys while it has the focus, or a click on a row; it snaps to the row in the lit middle band and takes it there. Without a time the wheels suggest 09:00 dimmed; turning any of them sets the start. A new start keeps the duration (at most up to 23:55); an end before the start becomes the start; without an end its minute wheel is dimmed. Typing turns the wheels as soon as the field reads as a time. The field follows the wheels: it selects the part that changed, and an end adds “ – ” and the end; typing a digit right behind a complete start adds “ – ” before it. “No time” clears both and closes the popover, “No end” clears the end (ruled out without an end).
  - **Repeat** reads “Daily”, “Weekly”, “Monthly on day 13”, “Monthly 2nd Fri”, “Yearly” or “Every 2 weeks”. The popover shows Never, Daily, Weekly, Monthly and Yearly as pills in one row (built like the date pills, the chosen one as an accent tint); Weekly adds the weekday chips (the date's weekday first), Monthly the choices that fit the date (“On day N”, “Nth weekday” for the 1st to 4th, “Last weekday” in the last week); every choice but Never has “every N day(s)/week(s)/month(s)/year(s)”. An end set with “End series here” is shown as “Ends after …” and kept. A repeat makes the entry a series.
  - **Tag** shows the chosen tag with its icon in its color. The popover lists “No tag” and the tags of `Config.md` in alphabetical order as chips with icon and color; a tag that is not configured is offered too, so that it is not lost. Picking one closes the popover.
  - **Location** shows no value, only its icon, lit in the accent when a location is set. The popover has a field and below it up to eight locations used before, most recent first, filtered by what is typed; a click takes one.
  - **Notes** (the token and field are labeled “Notes”) shows no value, only its icon, lit in the accent when there is a note. The note is written straight into its popover, without a field frame of its own, without bullets and without a resize handle; the popover is as tall as the date popover and its edge lights up while the note has the focus. The note is stored as free text exactly as it stands (see [DataFormat](../DataFormat.md#calendar)); a dash the user types is part of the text: `Enter` on a line that starts with “-” continues it with “- ” on the next line, and on a line that is only the dash it removes the dash.
- `Tab` moves from duplicate, delete and close through the title and the tokens to Apply (skipping hidden and disabled buttons) and opens each token's popover with the focus in its field or on its current choice; `Shift+Tab` moves back. Leaving a popover keeps what it holds. Inside a popover the arrow keys move between its choices (up and down by weeks in the calendar) and `Space` picks one.
- `Enter` applies the dialog from everywhere except the close, delete and duplicate buttons, also from a popover, whose value it takes first; in the note `Enter` starts a new line and `Ctrl+Enter` applies. `Esc` closes an open popover first, dropping what was typed in it, then the dialog; `Space` or a click opens a token.
- **Duplicate** turns the open dialog into a new item with what it holds, starting today (a range keeps its length, a repeat follows the new day, a backlog entry stays in the backlog). The dialog stays open with the focus in the title and the date popover open, so that another day can be chosen; delete and duplicate disappear as for any new item. A notification “Entry duplicated” or “Series duplicated” names the title. Nothing is created until Apply, which then creates and confirms it like a new item; closing drops it. The item the dialog was opened for stays unchanged.
- **Delete** (trash): for an entry or multi-day entry it deletes it (“Delete”); for an occurrence of a series (“Delete…”) it opens a small menu 8px below it, right-aligned with it and built like the context menu, with “Delete this occurrence” (calendar icon) and “Delete whole series” (repeat icon) in `--danger` and “End series here” (range icon; this occurrence stays the last one). The arrow keys move between its items, `Enter` picks one, `Esc`, a second click on the trash button or a press outside closes it. Moving an entry to the backlog is choosing “Backlog” as its date.
- Invalid typed dates, times or intervals are rejected with a notification, the previous value stays and the focus remains in the popover. On Apply, blank lines inside the note stay and blank lines before and after it are dropped.

## Notifications

- Appear in the bottom right corner as a stack of cards 270px wide (narrower on small screens), above the main panel and the backlog panel. While the entry dialog is open they appear above it and its blurred backdrop and stay usable there. Text is left-aligned; buttons sit at the bottom right.
- Each notification has three parts: the **severity** as a colored dot (info accent, warning yellow, error red), the **title** and an optional **body** below a thin line, indented to the title.
- Used for results and hints, for example creating, copying, cutting, pasting and deleting, import results, reloads after external changes, the attempt to drag an occurrence of a series, and errors.
- The title names the action or the problem, without the data it concerns, as the object and what happened to it: Entry created, Series created, Entry duplicated, Series duplicated, Contact created, Entry copied, Entry cut, Entry deleted, Series ended, Occurrence deleted, Folder opened, File reloaded, Events imported, Invalid time, Folder not found, Occurrence not moved. Pasting confirms the same way: Entry pasted. Actions on several entries count them: 3 entries copied, 3 entries cut, 3 entries pasted, 3 entries deleted. Copying a contact's text is another kind of action and says Copied to clipboard.
- Creating an entry, series or multi-day entry in the entry dialog names it and where it went: its date, its two dates or Backlog. Creating a contact shows the title only, since the new contact has no name yet.
- The body says what exactly, without prose, each fact on its own line: the entries concerned (at most three titles, then “and N more”), the contact, folder or file, the date, counts, and for problems why and what helps when that is not obvious (Use *HH:MM*. / Set it up with [New calendar].). Obvious hints are left out: no shortcuts such as undo, paste or save, nothing that repeats the title (Nothing to paste needs no “The clipboard is empty.”), no obvious next step (try again, reopen the folder) and never what the notification's own buttons do; their labels say it. A notification may have a title only. Errors also show their code and offer copyable details.
- Notifications use no quotation marks. Names the user gave or that identify data (entries, series, contacts, folders, files, formats) are highlighted: italic, bold, in the accent color. Buttons and functions of MD_Calendar named in the text (such as New calendar) appear as a small control chip. Line breaks separate what happened from what to do; within a sentence the text wraps on its own and avoids single words on the last line.
- When a file changed or was deleted outside the app while local changes exist, a warning stays until the user chooses “Reload” (discard local changes) or “Overwrite” (save local changes over the file). Its text names only the files. The buttons stand at the bottom right: “Overwrite” on the left in the yellow of unsaved changes (it overrides the file), “Reload” on the right in the green of the saved state (the safe choice). Meanwhile the save control stays in its unsaved state and saving shows the choice again.

## Settings

Scheme, background lights, borders and past dimming are fixed (see [Design System](DesignSystem.md)). Besides the views, the user controls the [sound toggle](#sound-toggle) and the options menu:

- **Hide icons** (switch, off by default) hides the tag icons on entries and multi-day bars in all views and in the backlog. The series icon always stays, because it says that an entry repeats, and so do the icons of the day badges (heart, gift, calendar star). Colors, titles and times stay. The choice is kept per device in `localStorage`.
